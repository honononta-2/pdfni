Fast, deterministic PDF table extraction in pure Rust.

pdfni extracts ruled and borderless tables — plus reading-order text blocks and Markdown — directly from digital-native PDFs without OCR, ML models, or external runtime dependencies. Run the same core engine in Rust, CLI, Python, C ABI, and WebAssembly.

Details & Architecture

Built end-to-end for coordinate accuracy and speed.

Table extraction quality depends on accurate glyph bounding boxes and vector ruling lines. Rather than wrapping an external PDF library, pdfni includes a pure-Rust PDF reader built on Mozilla pdf.js and tailored specifically for this library, resolving coordinates and layout in a single pass.

1. PDF Bytes Input
Encrypted (RC4 / AES-128 / AES-256), rotated pages, CJK CMaps, page/region filters.
→
2. Pure-Rust Reader
Built on Mozilla pdf.js and tailored for pdfni. Extracts top-down glyph coordinates, vector edges, and graphics in one pass.
→
3. Dual Table Detectors
lattice (ruled edges) followed by text (borderless alignment) without overlap under Auto.
→
4. Structured Outputs
Tables JSON (Document), reading-order blocks (DocDoc / DocContent), or Markdown.

Deterministic Rule-Based Engine

Works directly from glyph coordinates and vector lines with no ML weights or OCR. Identical input always yields identical output.

Ruled & Borderless Auto Mode

Automatically runs the ruled-line lattice detector first, masks confirmed regions, and runs the text alignment detector on remaining areas — or select either manually.

Built-in Pure-Rust PDF Reader

Built on Mozilla pdf.js and tailored specifically for pdfni. Handles encrypted PDFs (Standard Security Handler R2–R6), page rotation normalization, bundled Adobe CJK CMaps, and 512 MiB default decompression-bomb caps.

Parallel Native & GIL Release

Processes pages in parallel on native targets and releases the Python GIL, while producing identical output ordering in sequential WebAssembly builds.

Reading-Order & Markdown

Reuses the same single content-stream pass to emit headings, lists, headers/footers, and tables in reading order, plus opt-in Markdown export via the markdown feature.

Multi-Target Distribution

Available as a Rust crate, standalone CLI, dependency-free Python wheel (3.10+, free-threaded & abi3t support), native C ABI library, and browser/Node.js WebAssembly module.

Environment, Versions & Evaluation Protocol
  • Machine: Apple M2 (8 cores), 16 GB RAM, macOS 27.2 · Python 3.12.13 · OpenJDK 17 (-Xmx4g).
  • Libraries tested: pdfni 0.3.0 (default auto), tablers 0.9.0 (Rust + PDFium, find_tables + to_list), pdf_oxide 0.3.78 (PdfDocument.extract_tables), pymupdf 2.1 (use_layout=False, rule-based), pdfplumber 0.11.11 (page.find_tables), camelot 2.2.0 (flavor='auto', non-ML), tabula 2.11.0 (tabula-java 1.0.5 via jpype1).
  • Protocol: Full pipeline without ground-truth table regions; all outputs normalized to the same top-down Document JSON and scored by identical official evaluators (ICDAR 2013 dataset-tools, scitsr.eval). Speed measured in isolated subprocesses after a 1-PDF warmup, extracting full cell text. pdfni (Rust) is measured directly via pdfni::extract_from_bytes without Python dict conversion (Peak RSS: 17.6 MiB on ICDAR 2013, 11.2 MiB on SciTSR, 712.8 MiB on 2,380-page PDF).
  • Observed timeouts: camelot hit the 900 s cap on SciTSR after 2,643 / 3,000 docs and timed out after 600 s on the 2,380-page PDF.
Quick Start

Install and run in seconds.

Use the same extraction engine across Rust, CLI, Python, and WebAssembly. Switch tabs below for each target.

Install 
cargo add pdfni
Extract tables from bytes 
use pdfni::{ExtractOptions, extract_from_bytes};

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let bytes = std::fs::read("input.pdf")?;
    let doc = extract_from_bytes(&bytes, None, &ExtractOptions::default())?;
    println!("{}", serde_json::to_string_pretty(&doc)?);
    Ok(())
}

Use extract_content_from_bytes or extract_document_from_bytes for reading-order blocks, or enable the markdown feature for extract_markdown_from_bytes.

Install 
cargo install pdfni
Run from terminal 
# Extract tables only (Document JSON)
pdfni --output tables input.pdf output.json

# Extract ruled tables from selected pages to stdout
pdfni --output tables --mode ruled --pages 1,3-5 input.pdf

# Default: text blocks and tables in reading order (content JSON)
pdfni input.pdf output.json

Use --output doc for the full document model, plus --region, --detect-header-footer, and password flags for encrypted PDFs.

Install (Python 3.10+, zero runtime dependencies) 
pip install pdfni
Extract tables 
import pdfni

doc = pdfni.extract_tables_from_pdf("input.pdf")
for page in doc["pages"]:
    for table in page["tables"]:
        print([[cell["text"] for cell in row] for row in table["data"]])

For reading-order text blocks and tables together, use extract_content_from_pdf or extract_document_from_pdf. Supports pages, region, mode, and password keyword arguments.

Build with wasm-pack 
wasm-pack build --release --target web
Run in the browser 
import init, { extract_tables_from_pdf } from "./pkg/pdfni.js";

await init();
const bytes = new Uint8Array(await file.arrayBuffer());
const doc = JSON.parse(extract_tables_from_pdf(bytes));

Pass --features markdown to include extract_markdown_from_pdf, or trim cmap-* features to shrink bundle size.

Try pdfni directly in your browser (WebAssembly)

Drop any PDF into the standalone demo page to test table extraction, CSV download, reading-order JSON, Markdown preview, and visual region selection — 100% locally in your browser with no server uploads.
